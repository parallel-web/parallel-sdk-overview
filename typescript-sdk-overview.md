## Option A (recommended): Generate a single bundled `.d.ts` locally

### 1) Install deps
```bash
git clone https://github.com/parallel-web/parallel-sdk-typescript.git
cd parallel-sdk-typescript
npm install
```

### 2) Ensure the project emits declarations
Check `tsconfig.json` includes:
```json
{
  "compilerOptions": {
    "declaration": true,
    "emitDeclarationOnly": true,
    "declarationMap": false,
    "stripInternal": false
  }
}
```

Then build declarations:
```bash
npx tsc -p tsconfig.json
```

This should create `.d.ts` files in the configured `outDir` (commonly `dist/`).

### 3) Bundle to a single `.d.ts`
Use `@microsoft/api-extractor` (best at preserving types + docs):

```bash
npm i -D @microsoft/api-extractor
npx api-extractor init
```

Edit `api-extractor.json` to point at the entry `.d.ts` generated by `tsc`. Example:

```json
{
  "$schema": "https://developer.microsoft.com/json-schemas/api-extractor/v7/api-extractor.schema.json",
  "mainEntryPointFilePath": "<projectFolder>/dist/index.d.ts",
  "dtsRollup": {
    "enabled": true,
    "untrimmedFilePath": "<projectFolder>/parallel-sdk.d.ts"
  },
  "docModel": { "enabled": false },
  "apiReport": { "enabled": false }
}
```

Run:
```bash
npx api-extractor run --local
```

Output: `parallel-sdk.d.ts` (single-file footprint). This generally preserves doc comments; if any are missing, it’s usually because they didn’t survive to the emitted `.d.ts` due to how they were written/exported.
